# 7. TASK D — IMPLEMENT A QUALITY GATE

This is one of the most important requirements.

Implement a Champion vs Candidate model comparison system.

Definitions:

CHAMPION:
The currently approved model used by the existing prediction system.

CANDIDATE:
The newly trained model waiting for evaluation and possible promotion.

Quality gate requirements:

1. Evaluate the champion and candidate on the SAME held-out validation dataset.
2. Compare their performance.
3. Use appropriate quality metrics depending on the task.

For classification:

- Primary metric: Weighted F1-score.
- Additional metrics: Accuracy, Precision and Recall.

Default decision rule:

- Candidate must have a Weighted F1-score greater than or equal to the champion.
- Candidate must not reduce accuracy by more than a configurable tolerance.
- Candidate must have valid evaluation results.

For regression:

- Primary metric: RMSE.
- Additional metrics: MAE and R².

Default decision rule:

- Candidate RMSE must be lower than or equal to champion RMSE.
- Candidate R² must not be lower than champion R² by more than a configurable tolerance.
- Candidate must have valid evaluation results.

Make thresholds configurable instead of hardcoding them throughout the application.

Display a clear comparison:

| Metric | Champion | Candidate | Difference |
|---|---|---|---|

Possible quality-gate outcomes:

- ELIGIBLE_FOR_PROMOTION
- REJECTED
- NEEDS_REVIEW
- FAILED

A candidate should only be marked eligible if all required conditions are satisfied.

IMPORTANT SAFETY RULES:

- Never automatically overwrite the champion without recording the decision.
- Never promote a model that failed validation.
- Never delete the previous champion.
- Record the reason for acceptance or rejection.
- Preserve the candidate artifact even when it is rejected.
- Require an explicit user confirmation before promotion.
- Keep a history of every quality-gate decision.

Store:

- Champion run ID.
- Candidate run ID.
- Evaluation dataset ID.
- Champion metrics.
- Candidate metrics.
- Metric differences.
- Threshold configuration.
- Quality-gate result.
- Decision reason.
- Timestamp.
- User confirmation status.
- Promotion status.
